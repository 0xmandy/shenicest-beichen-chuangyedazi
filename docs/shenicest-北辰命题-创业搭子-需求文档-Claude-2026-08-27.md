## 二、产品定位

一句话：给北辰园区中小微创业企业的 AI 创业管家。企业把自己的基本情况交给管家一次，之后政策、融资、待办、风险到了该动手的时候管家主动提醒，人只做确认和决定。

形态：Web 端，手机壳尺寸展示（max-width 420px），与北辰现有小程序生态一致，方案文档里写明可平移为微信小程序。

与园区现有小程序的差异，一句话讲给评委：现有小程序是服务目录，企业要自己知道找什么；创业搭子把方向反过来，管家拿着企业画像去 175 条政策和 67 个金融产品里逐条比对，把「你符合什么、缺什么、去哪查原文」推到企业面前。人找服务变成服务找人。

用户两类，进入时必选身份，管家话术、任务、推荐全部按身份切换：

1. **已注册企业的创始人**。园区内 AI、机器人、数据服务类团队，5 到 50 人，没有专职政务专员、没有 CFO。痛点：政策看不懂也追不动、融资对接繁、合规事项漏办。
2. **尚未注册企业的更早期个人**。有方向没主体，可能已在接单试水。痛点：不知道从哪起步、不知道能领什么、不知道已经踩了风险。第二类对园区是招商漏斗最前端，管家陪着走到注册环节，注册地址与孵化载体自然导入北辰。

## 三、三条必走通的旅程

1. **入驻建画像**：进入 → 选身份（必选）→ 毕业状态、出海需求（可跳过）→ 画像生效 → 首页管家消息与全部推荐重算
2. **政策匹配申报**：政策页选行业 → 出匹配报告（匹配理由逐条回显 + 待核实项）→ 点进详情看官方原文 → 加入待办
3. **金融对接**：金融页勾融资条件 → 适配产品短名单（四要素原文）→ 点开看门槛原文 → 生成对接申请卡 → 按北辰 SOP 六步跟踪

三条旅程共用企业画像这一根数据主轴。这是和「五个功能模块拼一个门户」的本质差异，方案文档和路演反复讲这一句。

## 四、已实现的系统规格

### 4.1 数据层

**政策库**，来源 `政策智能体数据库.xlsx`，两张表：

- 表「整个文本导入接入」87 行 → **原文库 86 份**。第 62 行内容是字符串「Q&A」不是政策，剔除。
- 表「只有url接入到智能体」89 行 → **解读库 89 条**，标题、日期、URL 全部真实可点（ncsti.gov.cn / beijing.gov.cn）。
- 合计 **175 条**。

原样保留的字段：名称、原文件名、连接方式、连接状态、最近更新时间、发布日期、URL。
从标题派生的字段（仅供匹配用，界面上注明是派生的）：

- `level` 八档：朝阳区 / 北京市 / 中关村 / 经开区 / 通州区 / 昌平区 / 门头沟区 / 其他。原文库分布：朝阳区 39、北京市 38、其他 5、中关村 2、经开区 1、门头沟区 1。
- `tags` 十八类：人工智能、智能机器人、数据要素、知识产权、融资金融、中小企业、人才支持、场景开放、互联网3.0、医药健康、园区载体、成果转化、企业出海、信息软件、商务消费、高新技术、绿色制造、综合政策。每条最多 3 个。
- `type` 五档：申报通知 / 实施细则 / 管理办法 / 行动计划 / 支持措施 / 政策文件。
- `actionable`（仅解读库）：标题含申报、征集、揭榜、奖励、认定、资助、补贴、贴息、资金之一即为真。共 **27 条**。

**不派生的**：申报条件、补贴额度、截止日期。原表没有，编出来就是幻觉，界面上一律写「原库未结构化，以原文为准」。

**金融库**，来源 `金融资料.zip` 里的 `朝阳数据要素产业园金融工具统计_20260821.xlsx`，一张表两个区块：

- 主表 → **产品 67 个**。光大银行 29、浦发银行 12、北京银行 11、首创证券 5、中国银行 4、交通银行 3、光大证券 2、首正泽富 1。
- 附表「金融类政策」→ **可叠加的贴息补贴 9 条**（贷款利率下浮、创业担保贷款贴息、知识产权质押贴息、知识产权质押融资补贴、科技研发贷利率优惠、担保费率优惠、免担保费、数据资产费用补贴、区级数据要素贴息）。

原样保留：所属机构、产品名称、产品类型、适用门槛、核心特点、授信额度、期限周期、利率计息方式、补充说明。一个字不改写。
派生：`tags` 十四类（数据要素、知识产权、专精特新、科技型、纯信用、要抵押、供应链、跨境出海、股权投资、政策贴息、初创期、现金管理、个人金融、通用融资）、`debt` 布尔（债权类 51 / 股权与投行类 16）、`amountKnown` 与 `rateKnown`。

**关键数字，路演要讲**：67 个产品里只有 **28 个写了具体额度**、**13 个写了利率口径**，其余原表写「根据企业实际情况不定」。界面照实显示成「以机构核定为准」，不折算不估算。这比装作全都有数据更有说服力。

### 4.3 小事引擎（前后链路）

一句话进来，判成四类，各自落到不同地方。判定用正则，规则摆在界面上给评委看。

| 类型 | 判定 | 落到哪 |
|---|---|---|
| 疑问句 | `/[?？]\|吗\|呢\|怎么\|如何\|什么\|哪些\|多少\|多久\|有没有\|是不是/` | 广场公开卡 + 园区经验回答 + 政策类问题挂政策库原文 + 我的小事 |
| 感谢 | `/(感谢\|谢谢\|多谢\|多亏\|幸亏\|辛苦\|感恩\|thanks)/i` | 广场感谢卡 + 对方口碑 +1 + OPC Token 打赏 + 我的小事 |
| 完成态 | `/(开好\|办好\|搞定\|完成\|拿到了\|批下来\|已经\|终于\|通过了\|拿到\|下来了)/` 且非疑问 | 勾掉对应待办 + 日历那条标完成 + 移除对应风险 + 生成下一步进待办与日历 + 进度加分 + 我的小事 |
| 陈述句 | 以上都不是 | 看板（阶段、进度、待办、风险）+ 行政日历 + 广场一条仅自己可见的私密卡 + 我的小事 |

陈述句六条规则（营业执照 / 银行开户 / 补贴申报 / 报税 / 融资 / 客户拜访），每条带 stage、progress、stepIdx、todos（含 due 天数）、risks。完成态四条规则（银行 / 税 / 营业执照 / 补贴），每条带 match 正则、gain、next、resolve。

**与 coze 有数版的差别**：有数版「陈述句生成的待办进日历」只在预置数据里演示，代码没写这一段；本原型补上了真写入。机会一节有数版写死「北辰园区初创企业补贴最高50万」，本原型改为从政策库与金融库现取。

### 4.4 界面层（v3，08-27 晚改版）

底部四 tab：**首页 / 管公司 / 找机会 / 小事广场**。「我的」不占底部位置，从首页右上角头像进。原「服务」与原「风险」并进管公司，原「机会」改名找机会、内容不变。

- **首页**：管家消息卡（内容现算）→ 三张统计卡（待办滚到本页段落 / 风险跳管公司合规风险栏 / 机会跳找机会 tab）→ **猜您需要 4 个核心入口 + 展开收起** → 紧急待办。两张提醒卡、创业进度条、风险提示、推荐机会、近期日程五块已删，首页只留「管家在说什么 / 三个数 / 你可能要办什么 / 眼下要做什么」四段
- **管公司**：顶部两栏切换。经营事项栏分三组：有库内数据支撑六项（政策补贴 / 金融服务 / 融资机会 / 知识产权 / 找场地 / 招人用工）、通用办事流程四项（开公司 / 交社保 / 报税 / 行政日历）、更多服务折叠区五项（开单诊断 / 云服务规划 / 找顾问 / 五险一金 / 出海去，全部标演示内容）。合规风险栏是原风险页整页搬过来。tab 与分栏上的红色角标只数**高风险**条数，没有高风险就不亮
- **找机会**：三张数字卡 + 政策机会 + 金融机会 + 可叠加贴息，全部从两个库现取
- **小事广场**：园区活动卡 + 广场信息流 + 我的小事 + 右下角悬浮「+」记一件小事（v5 起首页右下角也有一颗，是老周的对话入口，见 4.8）

**v5 踩到的两个环境坑**：

1. macOS 上没有 `timeout` 这个命令，套上去直接 `exit 127`，还会把 dump 文件写成 0 字节，看着像页面炸了。要限时就用后台跑加轮询。
2. 无头 Chrome 截完图与 dump 完 DOM 之后进程不退，QA 脚本最后那句 `wait` 会一直挂着，两分钟超时。**产物其实早就写完了**，直接去看 `shot-*.png` 与 `dom-*.html` 就行，别以为脚本失败了重跑一遍。收尾 `pkill -f "user-data-dir=/tmp/cyd"` 清掉残留进程。

**3 自查**

```bash
# 抽出 <script> 段做语法检查
node --check check.js
# 无头 Chrome 截图看排版，把手机壳临时拉高才能一屏看完
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
  --hide-scrollbars --virtual-time-budget=4000 --window-size=440,2200 \
  --user-data-dir=/tmp/cc-qa --screenshot=out.png "file://$PWD/test.html"
```

测试页的做法：把原文件复制一份，`</head>` 前注入 `.phone-shell{max-height:none;height:2100px}`，`</body>` 前注入一段 setTimeout 脚本驱动到要看的状态（例如 `state.industry='智能机器人';finishOnboarding();openServiceDetail('政策补贴');`）。

**光看图不够，要让页面自己报溢出**。再注入一段探针遍历 `#app` 下所有元素，凡是 `scrollWidth - clientWidth > 2` 且自身不是滚动容器的就记下来，写进一个隐藏 div，然后用 `--dump-dom` 把结果 grep 出来。v5 一共 15 个状态各跑一遍截图与探针（v3 是 13 个，v5 补了老周办事流程回答卡这一个状态）。

grep 结果时要滤掉探针自己的源码：dump 出来的 DOM 里既有那段 `<script>` 原文、也有它写出来的隐藏 div，`grep -o "QAOVERFLOW\[[^]]*\]" | grep -v "bad.length"` 才是真结果。v5 15 个状态只有冷启动页报溢出，拿改动前的备份跑同一个探针也报（`onboarding active:450/420`），确认是原始 demo 自带的。

**v3 踩到的两个坑，写下来免得再踩**：

1. `.ev-generic` 是 flex 容器，模板里少写了一个 `</div>`，后面所有内容都被吸进去横排。改成 helper 函数生成，闭合标签只写一处。
2. `.page-scroll` 是 `display:flex; flex-direction:column`。**带 `overflow:hidden` 的 flex 子项会丢掉 `min-height:auto`**，容器高度不够时它会被压缩到 0。知识产权页的步骤清单就这么塌成了一条 2px 的线，短页面（开公司）却正常，靠肉眼很容易漏判。修法是 `.page-scroll > * { flex-shrink: 0 }`。
